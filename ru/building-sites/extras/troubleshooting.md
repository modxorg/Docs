Большинство проблем с управлением пакетами приходят от окружения сервера, а не от MODX. Проверьте перечисленные ниже причины.

## Не загружено расширение cURL

MODX спрашивает провайдеров по HTTP клиентом PSR-18, которому нужно расширение cURL. Менеджер проверяет его при открытии страницы. Без cURL над страницей появляется предупреждение, а кнопка **Download Extras** заменяется поиском по локальному каталогу.

Попросите хостинг включить расширение cURL.

## Каталог пакетов недоступен для записи

Пакеты распаковываются в `core/packages/`, и туда же пишутся архивы. Если PHP не может писать в этот каталог, скачивание и установка не проходят. Сделайте каталог доступным PHP для записи.

## Архив не распаковывается

На некоторых серверах есть сломанная сборка ZipArchive, и распаковка падает с ошибкой `extractTo` или `archiveTo`. Сообщение приходит из PHP, а не из MODX.

Установите системную настройку `archive_with` в **Да** (значение `1`). Тогда MODX распаковывает архивы через PCLZip, который поставляется с MODX и не требует расширений PHP.

## Архив отсутствует

Пакет, который установлен, но чей архив удалили из `core/packages/`, можно забрать у провайдера снова. MODX скачивает архив заново, когда он ему понадобится.

## Загрузка архива отклонена

Пункт **Upload a package** в меню кнопки **Download Extras** принимает только архив с именем `<signature>.transport.zip`. Файл с другим именем или не zip отклоняется с сообщением об этом.
