MODX 3 не сопоставляет хост с контекстом сам. Шлюз, который начинает запрос, выбирает его контекст, поэтому второму домену нужен второй шлюз.

У каждого домена здесь свой виртуальный хост и свой каталог на одной машине. Когда несколько доменов указывают на один виртуальный хост, контекст выбирает плагин. См. [Плагин шлюза](building-sites/contexts/gateway-plugin).

## Создание контекста

Создайте контекст в менеджере: **Админ** → **Контексты** → **Создать**. **Ключ контекста** — `dev`. Ключи `mgr`, `web` и `root` зарезервированы. Ключ начинается с буквы. Дальше допустимы буквы, цифры, дефис, точка и слэш. Подчёркивание отклоняется.

Затем создайте ресурсы домена в ветке этого контекста. Дерево выглядит так:

## Настройки контекста

Четыре настройки на вкладке **Настройки контекста** определяют, как собираются URL домена:

| Настройка | Значение |
| --- | --- |
| `base_url` | `/` |
| `http_host` | `dev.example.com` |
| `site_start` | ID ресурса, который открывает домен |
| `site_url` | `http://dev.example.com/` — схема, хост и путь, с косой чертой в конце |

Здесь можно переопределить и любую другую настройку. `cultureKey` задаёт язык домена. `session_handler_class` задаёт обработчик сессии этого шлюза. В значение вписывают имя класса. Смена настройки сбрасывает кэш контекста. Очищать кэш вручную не нужно.

## Каталог шлюза

Шлюз — отдельный каталог с четырьмя файлами:

| Файл | Что в нём |
| --- | --- |
| `index.php` | копия `index.php` из установки |
| `config.context.php` | ключ контекста |
| `config.core.php` | копия `config.core.php` из установки |
| `.htaccess` | копия `.htaccess` из установки |

Три копии указывают на одно и то же ядро и на одну и ту же базу. Между каталогами различается только контекст.

`index.php` работает как есть. Остальные три файла настраиваются так:

1. В `config.context.php` одна строка:

   ``` php
   <?php
   return 'dev';
   ```

2. В `config.core.php` записан абсолютный путь к ядру установки. Так его пишет установщик:

   ``` php
   define('MODX_CORE_PATH', '/home/example.com/public_html/core/');
   ```

3. В `.htaccess` нужна одна правка. `RewriteBase` должен указывать на каталог шлюза:

   ```
   RewriteBase /dev/
   ```

## Виртуальный хост

Веб-серверу нужен свой хост на этот каталог. Для Apache 2.4:

``` apache
<VirtualHost *:80>
    ServerName dev.example.com
    DocumentRoot /home/example.com/public_html/dev
</VirtualHost>
```

Перезапустите веб-сервер и откройте `http://dev.example.com/`. Ответит ресурс, названный в `site_start`.

## Ссылки между контекстами

Ссылка на ресурс другого контекста называет этот контекст:

```
[[~135:context=`web`]]
```

URL абсолютный, когда названный контекст не текущий. Ссылка без `context` остаётся относительной, если ресурс принадлежит текущему контексту. Если ресурс принадлежит другому контексту, ссылка становится абсолютным URL контекста, который записан у ресурса:

```
[[~135]]
```

То же в PHP:

``` php
$url = $modx->makeUrl(135, 'web');
```
