MODX 3 не сопоставляет хост с контекстом сам. Гейтвей, который начинает запрос, выбирает его контекст, поэтому второму домену нужен второй гейтвей: каталог со своим `index.php` и `config.context.php`, где назван контекст.

Пример ниже строит такой гейтвей для контекста `dev` на хосте `dev.example.com`.

## Создание контекста

Создайте контекст в менеджере: **Admin** → **Contexts** → **Create**. **Context Key** — это `dev`: именно ключ называет гейтвей, а имя свободное. Ключи `mgr`, `web` и `root` зарезервированы ядром.

Затем создайте ресурсы домена в ветке контекста. Дерево выглядит так:

## Настройки контекста

Четыре настройки на вкладке **Context Settings** контекста определяют, как собираются URL домена:

| Настройка | Значение |
| --- | --- |
| `base_url` | `/` |
| `http_host` | `dev.example.com` |
| `site_start` | ID ресурса, который открывает домен |
| `site_url` | `http://dev.example.com/` — схема, хост и путь, с косой чертой в конце |

Любую другую настройку здесь тоже можно переопределить — например, `cultureKey` для языка домена. Смена настройки сбрасывает кэш контекста, поэтому очищать кэш вручную не нужно.

## Каталог гейтвея

Гейтвей — это отдельный каталог с четырьмя файлами:

| Файл | Что в нём |
| --- | --- |
| `index.php` | копия `index.php` из установки |
| `config.context.php` | ключ контекста |
| `config.core.php` | копия `config.core.php` из установки |
| `.htaccess` | копия `.htaccess` из установки |

`index.php` работает как есть. Остальные три файла настраиваются так:

1. В `config.context.php` одна строка:

   ``` php
   <?php
   return 'dev';
   ```

2. В `config.core.php` — абсолютный путь к ядру установки, установщик пишет его именно так:

   ``` php
   define('MODX_CORE_PATH', '/home/example.com/public_html/core/');
   ```

3. В `.htaccess` нужна одна правка — `RewriteBase` должен указывать на каталог гейтвея:

   ```
   RewriteBase /dev/
   ```

## Виртуальный хост

Веб-серверу нужен собственный хост на этот каталог. Для Apache 2.4:

``` apache
<VirtualHost *:80>
    ServerName dev.example.com
    DocumentRoot /home/example.com/public_html/dev
    ErrorLog logs/dev-error_log
    CustomLog logs/dev-access_log
</VirtualHost>
```

Перезапустите веб-сервер и откройте `http://dev.example.com/` — ответит ресурс, названный в `site_start`.

## Ссылки между контекстами

Ссылка на ресурс другого контекста называет этот контекст:

```
[[~135:context=`web`]]
```

URL получается абсолютным, потому что ресурс лежит в другом контексте. Ссылка без контекста остаётся в контексте запроса и относительная:

```
[[~135]]
```

То же и в PHP:

``` php
$url = $modx->makeUrl(135, 'web');
```
