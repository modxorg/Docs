Дружественные URL (ЧПУ) заменяют адреса вида `index.php?id=42` на читаемые пути на основе псевдонимов ресурсов, например `/about/` или `/blog/my-post`.

Нужны две вещи:

1. Правила перезаписи на веб-сервере, которые направляют неизвестные пути в `index.php`
2. Включённые настройки дружественных URL в MODX

## 1. Настройте веб-сервер

**MODX Cloud:** правила перезаписи уже настроены — шаг можно пропустить.

Другие серверы: выберите руководство:

- [Apache](getting-started/friendly-urls/apache) (большинство shared-хостингов, файл `ht.access` → `.htaccess`)
- [IIS](getting-started/friendly-urls/iis) (`web.config` и URL Rewrite)
- [nginx](getting-started/friendly-urls/nginx)
- [lighttpd](getting-started/friendly-urls/lighttpd)

Пока перезапись не работает, включение дружественных URL в MODX приведёт к 404 на «красивых» путях.

## 2. Включите дружественные URL в MODX

В Менеджере откройте **Системные настройки** (иконка шестерёнки, верхняя навигация).

Отфильтруйте по ключу `friendly` (или Область: Дружественные URL), затем задайте минимум:

| Настройка | Ключ | Типичное значение | По умолчанию |
| --------- | ---- | ----------------- | ------------ |
| Использовать дружественные URL | `friendly_urls` | Да | Нет |
| Использовать дружественный путь псевдонима | `use_alias_path` | Да (полный путь от родителей) | Нет |

Необязательно: [friendly_urls_strict](building-sites/settings/friendly_urls_strict) отдаёт 404 для неизвестных псевдонимов вместо подстановки заголовка страницы.

При **Использовать дружественный путь псевдонима** = «Нет» ресурсы ведут себя так, будто лежат в корне сайта, без учёта родительских папок.

Контейнерные ресурсы (папки) используют настройку [container_suffix](building-sites/settings/container_suffix) (по умолчанию `/`) вместо `friendly_url_prefix` / `friendly_url_suffix`, удалённых в пользу [типов контента](building-sites/resources/content-types). Действует только для папок с HTML-типом контента.

Для нелатинских заголовков настройте транслитерацию псевдонимов (`friendly_alias_translit`: `none` (по умолчанию), `iconv`, `iconv_ascii` или именованная таблица): [Транслитерация псевдонимов](getting-started/friendly-urls/transliteration).

## 3. Добавьте base href в шаблоны

Поместите это в `<head>` каждого шаблона, который отдаёт HTML:

``` html
<base href="[[!++site_url]]" />
```

Относительные URL ресурсов будут разрешаться от корня сайта даже на вложенных путях дружественных URL.

## 4. Очистите кеш сайта

При сохранении этих настроек MODX сам перестраивает URI и перезагружает конфиг. Если фронтенд всё ещё отдаёт устаревшие ссылки или страницы, очистите кеш в Менеджере (или удалите `core/cache/`) — это же нужно после правок псевдонимов и шаблонов.

## Формирование ссылок

Предпочитайте теги ссылок, чтобы URL оставались корректными при перемещении ресурсов:

``` html
<a href="[[~1]]" title="Some title">Some Page</a>
```

Синтаксис тегов ссылок описан на странице [Ресурсы](building-sites/resources).

## Необязательно: редиректы www и HTTPS

Когда ЧПУ работают, выберите один канонический хост (`www` или домен без www) и HTTP или HTTPS — дублирующиеся имена хостов вызывают проблемы с сессиями и SEO.

На Apache в поставляемом `ht.access` есть закомментированные примеры правил: раскомментируйте нужный блок и замените домен. См. [руководство по Apache](getting-started/friendly-urls/apache).

На nginx эквивалентную логику `return 301` поместите в соответствующие блоки `server`.
