Дружественные URL (ЧПУ) заменяют адреса вида `index.php?id=42` на читаемые пути на основе псевдонимов ресурсов, например `/about/` или `/blog/my-post`.

Нужны две вещи:

1. Правила перезаписи на веб-сервере, которые направляют неизвестные пути в `index.php`
2. Включённые настройки дружественных URL в MODX

## 1. Настройте веб-сервер

**MODX Cloud:** правила перезаписи уже настроены. Пропустите этот шаг и перейдите к настройкам в Менеджере ниже.

Остальным: выберите руководство для вашего сервера:

- [Apache](getting-started/friendly-urls/apache) (большинство shared-хостингов, файл `ht.access` → `.htaccess`)
- [IIS](getting-started/friendly-urls/iis) (`web.config` и URL Rewrite)
- [nginx](getting-started/friendly-urls/nginx)
- [lighttpd](getting-started/friendly-urls/lighttpd)

Пока перезапись не работает, включение дружественных URL в MODX приведёт к 404 на «красивых» путях.

## 2. Включите дружественные URL в MODX

В Менеджере откройте **Системные настройки** (иконка шестерёнки в верхней навигации, затем «Системные настройки»).

Отфильтруйте по ключу `friendly` (или установите фильтр «Область» на «Дружественные URL»). Задайте минимум:

| Настройка | Ключ | Типичное значение |
| --------- | ---- | ----------------- |
| Использовать дружественные URL | `friendly_urls` | Да |
| Использовать дружественный путь псевдонима | `use_alias_path` | Да (полный путь от родителей) |

Если **Использовать дружественный путь псевдонима** установлено в «Нет», псевдонимы ведут себя так, будто каждый ресурс лежит в корне сайта, без учёта родительских папок в дереве.

Связанная настройка: [use_frozen_parent_uris](building-sites/settings/use_frozen_parent_uris) (по умолчанию Нет) делает URI дочерних ресурсов относительными к замороженному URI родителя вместо его текущего псевдонима — полезно, когда родители часто меняются.

Контейнерные ресурсы (папки в дереве) используют настройку [container_suffix](building-sites/settings/container_suffix) (по умолчанию `/`) вместо старых `friendly_url_prefix` и `friendly_url_suffix`, которые убрали в пользу [типов контента](building-sites/resources/content-types).

Для нелатинских заголовков настройте транслитерацию псевдонимов (`friendly_alias_translit`, iconv или пакет Translit): [Транслитерация псевдонимов](getting-started/friendly-urls/transliteration).

## 3. Добавьте base href в шаблоны

Поместите это в `<head>` каждого шаблона, который отдаёт HTML:

``` html
<base href="[[!++site_url]]" />
```

Относительные URL ресурсов будут разрешаться от корня сайта даже на вложенных путях дружественных URL.

## 4. Очистите кеш сайта

Очистите кеш в Менеджере (или удалите `core/cache/`), чтобы ссылки на фронтенде подхватили новые настройки.

## Формирование ссылок

Предпочитайте теги ссылок, чтобы URL оставались корректными при перемещении ресурсов:

``` html
<a href="[[~1]]" title="Some title">Some Page</a>
```

Синтаксис тегов ссылок описан на странице [Ресурсы](building-sites/resources).

## Необязательно: редиректы www и HTTPS

Когда ЧПУ работают, выберите один канонический хост (`www` или домен без www) и HTTP или HTTPS. Это предотвращает проблемы с сессиями и SEO из-за дублирующихся имён хостов.

На Apache примеры правил лежат в поставляемом файле `ht.access` (закомментированы). Раскомментируйте только нужный блок и замените пример домена. Подробности в [руководстве по Apache](getting-started/friendly-urls/apache).

На nginx эквивалентную логику `return 301` поместите в соответствующие блоки `server`.

## Устранение неполадок: 404 на «красивых» путях

- «Красивые» пути отдают 404, а `index.php?id=42` работает → правила перезаписи отсутствуют или неверны для вашего сервера — вернитесь к шагу 1.
- Сломались CSS/JS после включения FURL → добавьте `<base href>` в шаблоны (шаг 3).
- Ссылки не изменились после включения `friendly_urls` → очистите кеш (шаг 4); уже сохранённые ресурсы хранят свой alias, пока вы их не отредактируете.
- Запросы к файлам `core/` отдают 404 → это ожидаемо; `core/` должен оставаться закрытым ([Усиление безопасности MODX](getting-started/maintenance/securing-modx)).
