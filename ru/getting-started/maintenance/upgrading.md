- Обновление **с 2.x до 3.0+**: setup принимает только **2.6.0 и новее**. Сначала прочитайте [Обновление с 2.x до 3.0](getting-started/upgrading-to-3.0). Меняются пространства имён, процессоры, фиксированный путь к core и требования к PHP.
- Убедитесь, что хостинг соответствует актуальным [требованиям к серверу](getting-started/server-requirements). **MODX 3.2+ требует PHP 8.1 или выше** (в 3.0 изначально допускался PHP 7.2+). Учтите: собственная проверка PHP в setup по-прежнему пропускает 7.4 (см. [modxcms/revolution#17039](https://github.com/modxcms/revolution/issues/17039)); источник истины — `composer.json` и страница требований к серверу.
- Обновление с Evolution (1.x) официально не поддерживается. Исторические заметки — в разделе [Обновление с MODX Evolution](getting-started/maintenance/upgrading/evolution).

## Обновление MODX Revolution

Шаги ниже рассчитаны на стандартную установку. Для пользователей Git см. [Установка с Git](getting-started/installation/git "Установка с Git").

**Последний релиз MODX Revolution можно скачать на** **<https://modx.com/download/>**

Перед обновлением сделайте резервную копию файлов и базы данных: обычно всё проходит гладко, но помогает только копия. Обновите и пакеты: устаревшие дополнения часто вызывают фатальные ошибки после обновления ядра и могут заблокировать доступ к Менеджеру.

Проверьте перед обновлением:

- версии PHP и базы данных соответствуют [требованиям к серверу](getting-started/server-requirements) для целевого релиза;
- пакеты обновлены;
- вы вышли из MODX: в меню пользователя (справа сверху) выберите **Доступ → Завершить все сеансы** (разрешение `flush_sessions`; оно также завершает сеансы всех остальных пользователей);
- файлы в папке `core/cache` удалены.

## Загрузка файлов

Не загружайте распакованные локально файлы по FTP: FTP может пропустить или повредить файлы и намного медленнее файлового менеджера на сервере. Если сам менеджер не умеет распаковывать архивы, поищите в панели управления скрипт распаковки.

Для традиционного дистрибутива загрузите копию нужного MODX.zip на сервер, распакуйте его в новую папку на сервере и объедините все извлечённые файлы с корнем установки MODX. После этого удалите MODX.zip и новую папку: в корне должны оказаться объединённые файлы и новая папка `setup`.

Для продвинутого дистрибутива сделайте то же самое, но только для каталогов `core/` и `setup/`, и убедитесь, что каталоги `manager` и `connectors` вместе с файлами доступны для записи.

Не перезаписывайте `core/config/config.inc.php` и убедитесь, что он доступен для записи. Также не перезаписывайте и не удаляйте каталог `core/components/`.

Обновлённые файлы должны попасть *внутрь* существующих каталогов, а не заменять их. Нужен FTP-клиент с поддержкой **слияния каталогов** или, что лучше, файловый менеджер либо скрипт распаковки на сервере. На OS X: [Coda](http://panic.com/coda/) и [Transmit](http://panic.com/transmit/).

**Не перезаписывайте каталоги:** FTP-программа должна *сливать* папки, а не перезаписывать их.

### На OS X

При перетаскивании друг на друга Finder *заменяет* каталоги и может удалить `core/config/config.inc.php`. Слияйте из командной строки. Пример команды `ditto` после распаковки zip:

``` bash
ditto modx-3.2.0-pl /www/public_html/modx/
```

Тот же эффект даёт **cp**:

``` bash
cp -fr modx-3.2.0-pl/* /www/public_html/modx
```

Флаг «-fr» принудительно копирует рекурсивно (слияние каталогов). Обратный слэш перед `cp` убирает запрос «Вы уверены?» на каждую перезапись.

## Запуск Setup

В браузере откройте [yourSite.com/setup](http://yourSite.com/setup), выберите язык и следуйте мастеру установки или обновления.

Обновление обычно уже выбрано. Если нет, выберите «Обновление существующей установки», чтобы не перезаписать базу данных. Вариант «Новая установка» перезапишет базу. Для базы с другими параметрами подключения есть ещё «Расширенное обновление».

При обновлении **продвинутым** дистрибутивом снимите флажки «Базовый пакет распакован вручную» и «Файлы уже размещены» и убедитесь, что каталоги `core/`, `manager/` и `connectors/` доступны для записи.

Если во время setup возникают ошибки, прочитайте [Проблемы установки](getting-started/installation/troubleshooting "Проблемы установки") и [Решение проблем с обновлением](getting-started/maintenance/upgrading/troubleshooting "Решение проблем с обновлением").

## После Setup

После завершения setup удалите каталог `setup/` последней опцией мастера, чтобы никто не смог запустить setup повторно и сломать сайт.

Файл `config.inc.php` должен иметь права CHMOD 644.

После обновления очистите кэш браузера: браузеры кэшируют JS и CSS, а вам нужны свежие файлы.
