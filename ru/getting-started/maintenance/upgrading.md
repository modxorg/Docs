Этот документ описывает стандартный процесс обновления существующей установки MODX Revolution (обычно в линейке 3.x или с недавнего сайта 2.x после планирования изменений для 3.0).

- Обновление **с 2.x до 3.0+**: setup принимает только **2.6.0 и новее**. Сначала прочитайте [Обновление с 2.x до 3.0](getting-started/upgrading-to-3.0). Меняются пространства имён, процессоры, фиксированный путь к core и требования к PHP.
- Убедитесь, что хостинг соответствует актуальным [требованиям к серверу](getting-started/server-requirements). **MODX 3.2+ требует PHP 8.1 или выше** (в 3.0 изначально допускался PHP 7.2+).
- Обновление с Evolution (1.x) официально не поддерживается. Исторические заметки [здесь](getting-started/maintenance/upgrading/evolution).

## Обновление MODX Revolution

В этом документе предполагается обновление со стандартной установки. Для пользователей Git см. [Установка с Git](getting-started/installation/git "Установка с Git").

**Последний релиз MODX Revolution можно скачать на** **<https://modx.com/download/>**

Обязательно сделайте резервную копию файлов и базы данных перед обновлением. Обычно всё проходит гладко, но резервная копия **всегда** разумная практика.

Перед началом обновления убедитесь, что все пакеты актуальны и работают на текущей версии. Устаревшие дополнения часто вызывают фатальные ошибки после обновления ядра и могут заблокировать доступ к менеджеру.

Чеклист перед обновлением:

- Проверьте, что версии PHP и базы данных соответствуют [требованиям к серверу](getting-started/server-requirements) для целевого релиза
- Обновите пакеты, если нужно
- Выйдите из MODX (используйте «Завершить все сеансы и выйти» в меню менеджера)
- Удалите файлы в папке core/cache

## Загрузка файлов

Как правило, лучше не использовать FTP для загрузки файлов, извлечённых локально. FTP может пропустить или повредить файлы, что приведёт к ошибкам установки. Это также намного медленнее, чем файловый менеджер на сервере. Если файловый менеджер сервера не умеет распаковывать архивы, проверьте панель управления на наличие скрипта распаковки.

Для традиционного дистрибутива загрузите копию нужного MODX.zip на сервер и распакуйте файлы в новую папку на самом сервере.

Откройте новую папку, выберите все извлечённые файлы и объедините или скопируйте их в корень установки MODX. После этого можно удалить MODX.zip и временную папку с сервера. В корне установки MODX должны оказаться объединённые файлы и новая папка «setup».

Для продвинутого дистрибутива сделайте то же самое, но только для каталогов core/ и setup/. Убедитесь, что каталоги manager и connectors и их файлы доступны для записи.

Не перезаписывайте core/config/config.inc.php и убедитесь, что он доступен для записи. Также не перезаписывайте и не удаляйте каталог core/components/.

Здесь важен FTP-клиент с поддержкой **слияния каталогов**. Не нужно без разбора **перезаписывать** каталоги: обновлённые файлы должны попасть внутрь существующих. Пока нет самораспаковывающегося механизма обновления, **очень** удобно использовать FTP с слиянием каталогов или, что лучше, распаковку через файловый менеджер сервера, как описано выше.

На OS X можно купить одно из следующих приложений:

- [Coda](http://panic.com/coda/)
- [Transmit](http://panic.com/transmit/)

**Не перезаписывайте каталоги!**
Убедитесь, что FTP-программа _сливает_ каталоги, а не перезаписывает их!

## Запуск Setup

В браузере откройте [yourSite.com/setup](http://yourSite.com/setup). Выберите язык и следуйте процессу установки или обновления, выбрав нужный тип (обычное или с настройкой базы данных).

Обновление обычно уже выбрано. Если нет, выберите «Обновление существующей установки», чтобы не перезаписать базу данных. Вариант «Новая установка» перезапишет базу.

При обновлении **продвинутым** дистрибутивом снимите флажки «Базовый пакет распакован вручную» и «Файлы уже размещены» и убедитесь, что каталоги core/, manager/ и connectors/ доступны для записи.

Если во время setup возникают ошибки, прочитайте [Проблемы установки](getting-started/installation/troubleshooting "Проблемы установки") и [Решение проблем с обновлением](getting-started/maintenance/upgrading/troubleshooting "Решение проблем с обновлением").

## После Setup

После завершения setup удалите каталог setup/ последней опцией мастера, чтобы никто не смог запустить setup повторно и сломать сайт.

Файл config.inc.php должен иметь права CHMOD 644.

После обновления имеет смысл очистить кеш браузера. Браузеры часто кешируют JS и CSS, а вам нужны свежие файлы после обновления.

## Смотрите также

### Пользователи Mac OS X

При копировании распакованной папки в Mac OS X будьте осторожны: OS X «заменяет» папки при перетаскивании друг на друга. Используйте команду «ditto» из терминала, а не перетаскивание из Finder, иначе файл core/config/config.inc.php будет удалён. Пример команды ditto после распаковки zip:

``` bash
ditto modx-3.2.0-pl /www/public_html/modx/
```

Тот же эффект даёт команда **cp**:

``` bash
cp -fr modx-3.2.0-pl/* /www/public_html/modx
```

Флаг «-fr» принудительно копирует рекурсивно (слияние каталогов). Обратный слэш перед «cp» убирает запрос «Вы уверены?» на каждую перезапись.

См. заметку выше о FTP-клиентах с поддержкой слияния каталогов.
