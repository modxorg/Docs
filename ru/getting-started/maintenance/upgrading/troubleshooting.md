## Типичные проблемы

Сначала проверьте:

- вы прошли все шаги на странице [Обновление MODX](getting-started/maintenance/upgrading "Обновление MODX");
- вы загрузили все нужные файлы обновления и **объединили** каталоги, а не заменили их целиком;
- после обновления очистили кэш браузера — он снимает многие ошибки JS и CSS;
- очистили кэш сайта: setup очищает его не всегда, это зависит от окружения.

### Помощь! Доступен только пункт «New Installation», хотя это обновление

Так бывает, если удалён `core/config/config.inc.php`. Верните его: если перед обновлением была сделана резервная копия (это настоятельно рекомендуется), скопируйте файл оттуда в `core/config/` и сделайте доступным для записи.

Без копии создайте `core/config/config.inc.php` из шаблона `core/docs/config.inc.tpl`: подставьте значения вместо плейсхолдеров в `{}` и сделайте файл доступным для записи.

### Setup прошёл, но Менеджер работает не полностью

Очистите кэш браузера: он хранит JS и CSS Менеджера и после обновления продолжает тянуть старые файлы. После 2.0.2 это реже, потому что на файлы менеджера вешается cache-busting-токен в query-строке `?mv=<адлер32-хэш версии + uuid>`, который меняется после каждого обновления.

В MODX 3.x Менеджер отдаёт заранее собранные файлы JS и CSS. Пути `manager/min/` больше нет (каталог убрали в 3.0). Если страница пустая после обновления, очистите кэш браузера для хоста менеджера и проверьте, что компонент по-прежнему грузит свои файлы из `assets/components/<namespace>/` (его PHP живёт в `core/components/<namespace>/`).
