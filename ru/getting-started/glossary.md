## ACL

ACL (Access Control List, список контроля доступа): набор [разрешений](building-sites/client-proofing/security/policies/permissions), привязанный к объекту. Подробнее об ACL: на [Wikipedia](https://en.wikipedia.org/wiki/Access_control_list). Также [см. здесь](building-sites/client-proofing/security/policies/acls).

## Add-on

Сторонний компонент (3PC), который не меняет ядро и не расширяет его классы, но добавляет функциональность сайту MODX. Часто устанавливается через Extras (управление пакетами).

## Asset

Любой файловый ресурс, обычно в каталоге `/assets`, как задано `MODX_ASSETS_PATH`. Может включать фронтенд-файлы Extras, библиотеки, изображения, CSS, JavaScript и подобное.

## Back-end

Синоним интерфейса Менеджера MODX.

## Cache, caching

Хранение часто запрашиваемых данных, чтобы не повторять одни и те же обращения к базе. MODX кеширует конфигурацию, ресурсы, элементы, лексиконы и другое в `core/cache/`. [Подробнее](extending-modx/caching).

## Category

Необязательное классифицирующее имя для элементов, наборов свойств и некоторых других объектов, чтобы группировать связанные записи в Менеджере.

## Child Resource

Ресурсы выстроены в дерево. Когда ресурс является контейнером (родителем), ресурсы внутри него: его дочерние ресурсы.

## Chunk Tags

Теги вида `[[$ChunkName]]`, которые вставляют чанк.

## Component

Также называется сторонним компонентом или 3PC. Обычно Extra (дополнение), расширение ядра или пакет шаблонов, добавляющий функциональность.

## Connector

HTTP-точка входа для AJAX-запросов. Коннекторы загружают MODX, очищают запрос и передают его процессору. [Подробнее](getting-started/directory-structure#connectors).

## Content Type

Задаёт расширение, MIME-тип и флаг «двоичный» для ресурса. [Подробнее](building-sites/resources/content-types).

## Context

Группа ресурсов и настроек. Часто используется для мультисайта, нескольких языков или поддоменов.

## Context Setting

Настройка, действующая в одном контексте. Может добавить новый ключ или переопределить системную настройку для этого контекста.

## Core Workspace

Именованная запись ядра MODX, используемая сайтом. Обычная установка создаёт одно рабочее пространство по умолчанию, указывающее на пакет core. В повседневной работе с сайтами редко нужно управлять workspace вручную: этим занимаются установщик и управление пакетами.

## Document

Обычный тип ресурса для страницы сайта (класс `modDocument`).

## Document Identifier

См. идентификатор ресурса.

## Element

Шаблон, переменная шаблона, чанк, сниппет, плагин, категория или набор свойств в дереве элементов Менеджера.

## Extension

Также называется расширением ядра. Компонент, который заменяет или расширяет поведение ядра, например пользовательский класс аутентификации или механизм кеширования.

## File Resolver

Резолвер транспортного пакета, который копирует файлы из исходного пути пакета в целевой при установке или удалении.

## Form Customization

Правила, которые управляют видом и поведением форм Менеджера (поля, вкладки и связанный интерфейс). [Подробнее](building-sites/client-proofing/form-customization).

## Form Customization Set

Набор правил настройки форм для конкретной страницы Менеджера (action). [Подробнее](building-sites/client-proofing/form-customization/sets).

## Friendly URLs, Friendly aliases

SEO-дружественные URL (часто сокращают до FURLs или ЧПУ). При включённых дружественных URL ресурсы используют читаемые пути на основе псевдонимов вместо `index.php?id=…`. См. [Использование дружественных URL](getting-started/friendly-urls).

## Language Tags

Теги вида `[[%LanguageStringKey]]`, которые выводят записи лексикона.

## Lexicon

Словарь слов и фраз, организованный по культуре (например `en` или более конкретно `en-GB`). Используется для интернационализации Менеджера и Extras. Записи можно править в управлении лексиконами.

## Lexicon Topic (formerly Foci)

Набор записей лексикона по одной теме. MODX подгружает темы по запросу, чтобы снизить накладные расходы.

## Link Tags

Теги вида `[[~ResourceId]]`, которые выводят URL ресурса.

## Manager

Административный интерфейс MODX (бэкенд).

## Media Source

Настроенный источник медиафайлов: обычно локальная файловая система или удалённые бэкенды вроде Amazon S3. Драйверы можно установить как Extras. [Подробнее](building-sites/media-sources).

## Namespace

Организационный ключ для компонентов. Пространства имён группируют записи лексикона, настройки и связанные объекты и обычно задают путь, где лежит компонент.

## Package Management

Установщик в Менеджере (Extras → Installer), который загружает и устанавливает транспортные пакеты от провайдеров вроде modx.com. [Подробнее](building-sites/extras).

## Parent Resource

В дереве ресурсов контейнер, под которым лежат дочерние ресурсы.

## Placeholder Tags

Теги вида `[[+PlaceholderName]]`, которые выводят плейсхолдеры. Обычно их задают в сниппете или плагине через `$modx->setPlaceholder('placeholderName', 'value')`.

## Plugin

PHP-код, который выполняется на системных событиях (например при сохранении ресурса или очистке кеша) с доступом к API MODX. В отличие от сниппетов, плагины обычно не вызывают из тега на странице. [Подробнее](extending-modx/plugins).

## Property

Один именованный параметр элемента.

## Property Set

Именованный набор свойств, привязанный к элементу, чтобы передавать разные параметры без правки самого элемента.

## Renderer

Метод, который меняет способ отображения данных (например в пользовательской колонке таблицы). См. документацию Extra, где для пакета описаны рендереры.

## Resource

Любой объект в дереве ресурсов, который парсер может превратить в URL и контент: чаще всего документ, но также веб-ссылки, симлинки и статические ресурсы.

## Resource Field

Поле ресурса, например `pagetitle`, `longtitle`, `introtext`, `alias` или `menuindex`. Многие видны на экране создания/редактирования и через теги ресурса (`[[*pagetitle]]`). Остальные доступны через объект ресурса в PHP.

## Resource Identifier

Также document ID или resource ID: числовой идентификатор в дереве ресурсов, однозначно определяющий ресурс.

## Resource Tags

Теги вида `[[*fieldOrTvName]]`, которые выводят поля ресурса или переменные шаблона для текущего ресурса.

## Resource Tree

Иерархический список ресурсов в Менеджере (обычно слева). Структура здесь задаёт навигацию сайта и при включённых дружественных путях псевдонимов: URL.

## Resolver (from Transport Package)

Постпроцессор, который выполняется после сохранения объекта транспортного контейнера при установке или удалении. Примеры: привязка событий плагина или копирование файлов в `assets/`.

## Session

Период, в течение которого MODX узнаёт посетителя (или пользователя Менеджера) между запросами. Когда сессия заканчивается, следующий запрос считается от нового посетителя, пока он снова не пройдёт аутентификацию.

## Setting Tags

Теги вида `[[++SettingName]]`, которые выводят [системные настройки](getting-started/glossary#system-setting), [настройки контекста](getting-started/glossary#context-setting) или [настройки пользователя](getting-started/glossary#user-setting).

## Snippet

PHP-код, который вы вызываете со страницы (или из другого элемента) для динамической логики. [Подробнее](building-sites/elements/snippets).

## Snippet Tags

Теги вида `[[SnippetName]]` (вызовы сниппетов).

## Static Resource

Ресурс, контент которого читается из файла на файловой системе.

## Symlink

Ресурс, который повторно использует контент другого локального ресурса по другому URL.

## System Event

События, которые срабатывают при операциях MODX (сохранение, удаление, очистка кеша и т. д.). Плагины подписываются на эти события. [Подробнее](extending-modx/plugins/system-events).

## System Setting

Настройка на весь сайт. Настройки контекста и пользователя могут переопределять её для контекста или пользователя.

## Template Variables (or TVs)

Пользовательские поля, которые вы привязываете к шаблонам и редактируете на ресурсах. Указываются тегами ресурса, например `[[*MyTV]]`.

## Transport Package

Zip-архив транспортных контейнеров, который можно установить на сайт MODX (обновления ядра и Extras). [Подробнее](extending-modx/transport-packages).

## Transport Vehicles

Контейнеры внутри транспортного пакета, которые хранят объекты или файлы и знают, как их установить или удалить. [Подробнее](extending-modx/transport-packages#okay-what-are-these-vehicles).

## User Setting

Настройка для одного пользователя. Может добавить новый ключ или переопределить соответствующую настройку контекста или системы.

## Validator (from Transport Package)

Предпроцессор, который выполняется до установки или удаления транспортного контейнера. Если возвращает false, этот шаг установки или удаления пропускается. Типичные проверки: расширения PHP, права на запись каталогов, наличие нужных пакетов.

## Weblink

Ресурс, который перенаправляет на другой ресурс или внешний URL.

## xPDOVehicle

Базовый класс транспортного контейнера. Хранит объекты xPDO (строки данных) плюс атрибуты, управляющие установкой и удалением, включая валидаторы и резолверы.
