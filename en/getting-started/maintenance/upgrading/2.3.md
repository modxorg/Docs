The most important changes in MODX 2.3 (not a complete list):

| Change | What it gives you |
| --- | --- |
| URL-based routing instead of modAction | The URL names the action; modAction stays for backwards compatibility |
| More powerful namespaces: custom TV input types no longer need a plugin and can be read from specific directories | A custom TV input type can live in a directory instead of shipping a plugin |
| Much smaller number of connectors that need to be installed | Far fewer files to install |
| New interface design | The Manager gets a new look |
| New REST Server classes for building REST APIs on xPDOObjects. Example <https://gist.github.com/splittingred/2346752> | REST endpoints on top of xPDOObjects with little boilerplate |
| Manager themes now use Grunt and Sass, which allows quick major restyles in custom themes | A custom theme can be restyled in one build step |
| Settings can be applied at User Group level | A setting can differ per User Group |
| Contexts can be renamed | An existing Context gets a new name |
| CSS/JS compression can be disabled during setup | A way out when the compressor breaks the site |
| An "Other" gender option for user profiles | Profiles are not limited to two genders |
| A dedicated Media Manager page in the manager | Media files have their own page in the Manager |
| Previewing resources even when front-end sessions are disabled | Preview works on sites that disable visitor sessions |
| System settings (`welcome_action`/`welcome_namespace`) for the default action after login or when no `?a` var is passed | The screen shown after login is configurable |
| Editing a resource in a new window with shift or middle mouse button click on the resource tree | A resource opens in a second window while the tree stays put |
| The toPlaceholder output filter no longer returns its value | The filter sets the placeholder and prints nothing |
